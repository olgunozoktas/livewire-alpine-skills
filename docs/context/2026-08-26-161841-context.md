# Repository Context

## Purpose

This repository is the canonical source for two related agent skills.

- `livewire-development` covers Laravel Livewire v4 and relevant v3 differences.
- `alpinejs-development` covers Alpine.js v3 and its Livewire integration.

The Livewire skill is the stack entry point. Its `bin/stack.sh` tool locates the Alpine skill.

## Repository Structure

Each top-level skill directory is self-contained. Each directory contains a `SKILL.md`, a README, references, and validation tools.

The Livewire skill also contains test fixtures and executable recipes. The Alpine skill contains a static review tool and references.

The root README describes both skills. The root MIT license applies to the full repository.

## Runtime Contract

An agent reads each `SKILL.md` first. It reads a linked reference only when the task needs that topic.

The skills do not change an application by themselves. Their tools inspect, review, scaffold, evaluate, or validate project code.

`livewire-development/bin/scaffold.sh` is the only normal tool that writes application files. Other review and detection tools are read-only.

## External Sources

The Livewire content comes from the official Livewire `4.x` documentation. The version guide also compares the official `3.x` documentation.

The Alpine content comes from the official Alpine.js documentation. Livewire v4 bundles Alpine.js v3.

The root README records the last verified source versions and commits. Live documentation has priority when facts change.

## Validation

- Run `python3 livewire-development/bin/review.py --self-test` for the Livewire review rules.
- Run `python3 alpinejs-development/bin/review.py --self-test` for the Alpine review rules.
- Run `bash livewire-development/bin/eval.sh --compare` for the fixed evaluation fixtures.
- Run `bash livewire-development/bin/verify-recipes.sh` for the full recipe runtime gate.
- Run `bash livewire-development/bin/refresh.sh` to compare the snapshot with current official documentation.

The recipe gate can use Composer, PHP, and a temporary Laravel application. The refresh tool needs Git and network access.

## Source and Distribution

This repository owns the skill content. Other skill collections can vendor exact copies.

When a vendored copy changes, update this canonical repository in the same session. Record the source relation in the vendor registry.

## Hard Constraints

- Keep the two skills separate because Alpine also works without Livewire.
- Keep `livewire-development` as the common stack entry point.
- Prefer current official documentation over the stored snapshot.
- Keep all skill instructions and user messages in ASD-STE100 Simplified Technical English.
- Do not delete files during maintenance.
- Do not start a development server during validation.

## Truth Locations

- Skill routing and mandatory rules: each `SKILL.md`.
- Detailed technical facts: each `references/` directory.
- Measured coverage and source versions: the root README and skill READMEs.
- Executable checks: each `bin/` directory and the Livewire `tests/` directory.
- Repository architecture: the newest file in `docs/context/`.

## Known Traps

- Laravel Boost can provide another skill with the same name. The project-level copy has priority.
- Livewire v4 defaults differ from v2 and v3 training data.
- A Livewire task often also needs Alpine guidance. Use `bin/stack.sh` to load both maps.
- A copied skill can drift from this repository without a source registry entry.
